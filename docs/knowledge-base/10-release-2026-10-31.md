# 10 — Release 2026-10-31: hardening + compliance engine

What changed, what it means for users, and the exact commands to deploy it.

## What changed (plain language)

- **Security holes closed.** Nobody can make themselves an admin any more, lots can't skip the export check, and the DDS, settlement, spec sheet and cupping data are only visible to the people who should see them. Login is rate-limited and logout really logs you out.
- **The 7 compliance gates are now all automatic.** No gate can be ticked by hand — not even by an admin. Each one is worked out from real evidence every time a lot is saved:

  | Gate | Passes when… |
  |---|---|
  | GPS | the lot has a farm boundary or GPS point |
  | Deforestation-free | the satellite check finds no forest loss after 2020 inside the plot (re-run whenever the boundary changes) |
  | EUDR DDS | the platform generated and stored a DDS while the two gates above pass (redrawing the boundary invalidates it) |
  | Phytosanitary | a certificate is uploaded and not expired |
  | ECTA license | the exporter's license is uploaded, in date, **and verified by Beersheba staff** |
  | NBE FX | the declaration is uploaded |
  | Minimum price | the lot's FOB price is at or above the **floor price an admin has entered** |

- **Every gate change is recorded** in a tamper-evident log (each entry is chained to the previous one with a SHA-256 hash). Exporters see it on the lot page under "Compliance audit trail".
- **The lot page explains itself**: a readiness score, and for every failing gate the reason and the next step.
- **Offers and samples follow real rules**: minimum order, available stock, one contract per lot (competing offers are closed automatically), samples move pending → approved → shipped → received.
- **Daily automatic check** (Celery beat, 06:17 Addis time): expiries, license status, floor prices, and 30/7/1/0-day reminders.
- **Look and feel**: the back office now uses the Beersheba colours and fonts, the marketplace shows farm photos, and pages load faster (the initial download is about a third of its previous size).
- **Fixed silent bugs**: document uploads from the lot form were being thrown away; the settlement calculator ignored the exchange rate you typed; farm areas showed as negative numbers.

## Things that will look different right after deploy

1. **The "Minimum export price" gate fails on every lot until an admin enters floor prices.** This is deliberate — the platform must not claim a price check passed when no floor exists. Step 5 below fixes it.
2. **The "ECTA license" gate** stays green only for exporters whose lots had it ticked before (the migration carries that decision over). Everyone else needs a staff review on `/admin/licenses`.
3. **"Q-Grader" is no longer offered at sign-up.** Create grader accounts in Django admin (set Role = Q-Grader).

## Deploy commands (VPS)

Run these one block at a time and paste back any output that shows an error.

```bash
# 1. Get the code (after the pull request is merged into master)
cd ~/bunna-bridge
git checkout master
git pull origin master
```

```bash
# 2. One-off safety copy of the database before migrating (recommended even
#    though scheduled backups are not set up yet)
cd ~/bunna-bridge/bunna_bridge
docker compose -f docker-compose.local.yml -f docker-compose.vps.yml exec -T postgres \
  sh -c 'pg_dump -U "$POSTGRES_USER" "$POSTGRES_DB"' > ~/bunna-bridge-before-2026-10-31.sql
ls -lh ~/bunna-bridge-before-2026-10-31.sql
```

```bash
# 3. Apply database changes, then recompute every gate from evidence
cd ~/bunna-bridge/bunna_bridge
docker compose -f docker-compose.local.yml -f docker-compose.vps.yml run --rm django python manage.py migrate
docker compose -f docker-compose.local.yml -f docker-compose.vps.yml run --rm django python manage.py refresh_compliance
```

```bash
# 4. Restart Django + Celery so the new code and the daily schedule load
sudo systemctl restart bunna-bridge
sleep 10
docker compose -f docker-compose.local.yml -f docker-compose.vps.yml ps
curl -s -o /dev/null -w "API status: %{http_code}\n" https://bunnabridge.pro.et/api/v1/lots/
```

```bash
# 5. Rebuild and publish the frontend
cd ~/bunna-bridge/bunna-bridge-frontend
npm ci
npm run build
sudo rsync -a --delete dist/ /var/www/bunnabridge/
```

Then, in the browser:

6. **Enter floor prices**: Django admin → Lots → Floor Prices → Add. Leave grade/processing blank for a general minimum, or add more specific rows (e.g. G1 + washed). Use the current official minimum and note the directive in "Source". Saving recomputes every open lot.
7. **Review licenses**: log in as an admin on the site → sidebar → **License Reviews** → open each license → **Verify**.

### Demo logins on the live site

The sign-in page no longer lists any accounts. To have one login per role on the live site for demos — with **your own** password, because the default above is public in the code — run:

```bash
cd ~/bunna-bridge/bunna_bridge
docker compose -f docker-compose.local.yml -f docker-compose.vps.yml run --rm django \
  python manage.py seed_demo --users-only --password 'CHOOSE-A-LONG-PRIVATE-PASSWORD'
```

This creates `admin@`, `exporter@`, `buyer@`, `roaster@`, `farmer@` and `qgrader@demo.beersheba.et` only: no lots, offers or samples, and the demo admin is a platform admin but **not** a Django `/admin/` user. To remove them later, add `--reset` (it deletes only `@demo.beersheba.et` accounts and their data).

## New / changed API endpoints

| Endpoint | Purpose |
|---|---|
| `POST /api/v1/auth/logout/` | `{refresh}` — revoke a refresh token |
| `GET /api/v1/auth/license-reviews/`, `POST …/<id>/` | Staff: list / verify (`{"approve": true}`) ECTA licenses |
| `GET /api/v1/lots/<id>/compliance-events/` | Gate audit trail + `chain_valid` |
| `GET /api/v1/lots/<id>/eudr-geojson/` | Plot GeoJSON for the EU Information System (TRACES) |
| `POST /api/v1/sample-requests/<id>/received/` | Requester confirms delivery |
| `GET /api/v1/lots/?marketplace=1&page_size=N` | Public catalogue view; page size up to 500 |
| `GET /api/v1/lots/<id>/compliance-check/` | Now also returns `readiness_percent` and a per-gate `report` |

Removed: the cookiecutter `/users/…` HTML pages (unused; the SPA covers profiles).

## Urgent follow-up found 2026-11-01: exposed demo passwords

Every frontend build deployed before this release contains, in its sign-in page, plaintext passwords for six accounts (including an Admin). The new build removes them, but anyone may already have copied them. Run this on the VPS once — it lists which of those accounts exist on the live database and locks their passwords (the accounts and their data stay; set a new password afterwards in Django admin → Users → the user → "change password" link):

```bash
cd ~/bunna-bridge/bunna_bridge
docker compose -f docker-compose.local.yml -f docker-compose.vps.yml run --rm django python manage.py shell -c "
from bunna_bridge.users.models import User
emails = ['admin@bunnabridge.com', 'dawit@addiscoffee.et', 'sarah@nordicros.de',
          'james@brooklynroastery.com', 'abebe@kochere.et', 'tigist@scaethiopia.et']
for u in User.objects.filter(email__in=emails):
    u.set_unusable_password()
    u.save(update_fields=['password'])
    print('locked:', u.email, u.role, 'staff' if u.is_staff else '')
print('done')
"
```

If it prints `done` with no `locked:` lines, none of those accounts exist on production and nothing else is needed.
